# Tractor and yellow bus — design

Status: headless enrichment 2026-10-03 (quick mode, assumptions below) · Issue #6 · builds on #5 (vehicle table, merged)

## Goal

Two more entries in the `VEHICLES` table of `prototype/index.html`: a **tractor** (slow, enormous grip) and a **generic yellow bus** (12 m, sluggish, wide turns, heavy). Both are sized in real metres (`scale: 1.0`), their 3D models come from the **Kenney "Car Kit" (CC0)**, loaded as glTF from files vendored in the repo, and the asset source is credited in the game. The compact car keeps driving exactly as today (golden trace, 1e-6).

Success looks like:

- `VEHICLES.tractor` and `VEHICLES.bus` exist with the values under Decisions; `setVehicle(VEHICLES.bus)` works and the game drives, films, sounds and collides as a 12 m bus.
- A glTF model path exists: `model: 'gltf'` entries load a vendored `.glb`, fit it to the entry's real length, and show it in the game; physics never waits for the download.
- A long vehicle collides along its whole length (`collision: { shape: 'obb', hl, hw }`), not as one circle at its centre.
- A player can drive them today via `?vehicle=tractor` / `?vehicle=bus` in the URL; the picker UI is #7.

## Context (what the code does today)

- `VEHICLES` has one entry, `compact` (`prototype/index.html:855-861`): `model` is a builder id in `MODELS` (`:886`, only `compact: buildCompact`), `gltf: null` is reserved, `collision: { shape: 'circle', r: 1.3 }`, `mass` only softens the crash response in `collide` (`:991`).
- `checkVehicle` (`:893`) throws for any `model` not in `MODELS` ("glTF loading is not implemented yet") and for any `collision.shape !== 'circle'` ("OBB for long vehicles: #6"). `prototype/tests/test_vehicles.py::test_set_vehicle_validates_and_round_trips` asserts exactly these two errors (`"#6" in obb`, `"bus" in model`) — that test documents the deferred work this issue delivers and is rewritten here, not deleted.
- `collide(r)` (`:991`) tests one circle of radius `r = carRadius()` (`:895`) against the static obstacle grid: axis-aligned-in-local-frame boxes `{ x, z, hw, hd, c, s, h }` and circles (`circle: r`) pushed by `pushOBB` (`:480`); it displaces `P`, reflects the normal velocity with the literal restitution `1.25`, and scales speed loss and damage by `1 / VEH.mass`. There are **no movable obstacles**: houses, the Kreisel island, lamps and hydrants (`PROP_SOLID`, `:675`) are all static.
- `stepCar` (`:992-1008`) reads every per-vehicle number from `VEH.drive`; there is no surface-dependent drag (grass, field and asphalt drive the same), so "good on fields" has no mechanical hook today.
- Cameras read `VEH.camera` (`:1015-1024`); eye offsets are model metres × `VEH.scale`. `SFX.horn`/`SFX.update`/`hud()` read `VEH.sound` (`:936`, `:928`, `:1127`).
- three.js comes from the jsDelivr CDN through an import map that also maps `three/addons/` to `examples/jsm/` (`:198`). `three/addons/loaders/GLTFLoader.js` therefore resolves without any vendoring (checked: `https://cdn.jsdelivr.net/npm/three@0.170.0/examples/jsm/loaders/GLTFLoader.js` → HTTP 200, 110 KB). The *models* are vendored; the *library* stays where `three` already is.
- Async resources are awaited at module top level (`ASPHALT`, `:239`; terrain/world, `:357-359`). `setVehicle` is synchronous and the tests call `window.__mm.setVehicle(def)` then `window.__mm.sim(...)` immediately (`test_vehicles.py::use_vehicle`).
- The shadow blob is a circle of radius 2.6 scaled `(scale, 0.55·scale)` (`:887`, `:891`) and rotated with the car.
- Credits: there is no credits screen. The start panel carries a data-source line `#blurb` (`:194`, strings `blurbHand`/`blurbOsm` in `prototype/strings.js:26-27`); `README.md` has a License section listing OSM and swisstopo attributions (`README.md:51-58`, "Hand-made assets … license to be decided").
- `?debug` is parsed by `debugFromQuery(location.search)` (`prototype/debug.js:5`, used at `index.html:1126`) — the pattern for `?vehicle=`.
- Kenney Car Kit 3.1 (kenney.nl/assets/car-kit): CC0, FBX/OBJ/glTF, "45+ models including a sedan, van, ambulance and more", 8 separate wheel models. A tractor model (`tractor.glb`) is confirmed vendored from Car Kit 3.1 by a third-party project. **No bus is listed anywhere in the kit's description or tags** (sedan, van, ambulance, firetruck); the kit's long vehicles are the van, the delivery truck, the truck and the garbage truck. See A2.

## Decisions

| Topic | Decision | Rationale |
|---|---|---|
| Model files | Vendored under `prototype/models/car-kit/`: `tractor.glb`, the kit's `wheel-default.glb` (or whichever wheel file the kit ships for the tractor), plus `LICENSE.txt` (CC0 1.0 text + source URL + kit version). Any texture a `.glb` references externally (the kit's `colormap.png`) is vendored next to it. Loaded with relative URLs (`models/car-kit/<file>`), like `textures/asphalt_sisseln.jpg`. | Buildless stack: static files, no CDN at runtime for assets, same origin as the game. |
| Bus model | **Open — see A2.** The design and plan are written so the bus is a `model: 'gltf'` entry whose file is `prototype/models/car-kit/bus.glb`; if the Car Kit has no bus, the implementer uses a different CC0 file at that path (Quaternius, the issue's named alternative) or a procedural `buildBus` builder (yellow box body in the kit's flat-shaded style, kit wheels) and records which in `LICENSE.txt`/CHANGELOG. Whatever the model, the bus is yellow (`#f5c400`, the colour already used for bus-stop boards at `index.html:680`), has **no logo, lettering or livery details**, and keeps its 12 m × 2.55 m × 3.2 m footprint. | docs/07 decision 2026-10-01; the asset choice is the one point in this issue the repo gives no signal on. |
| glTF loader | `import { GLTFLoader } from 'three/addons/loaders/GLTFLoader.js'` next to the existing imports (`:200-201`). One `GLTFLoader` instance; loaded scenes cached per URL in a `Map` so a second `setVehicle` of the same vehicle does not refetch. | Resolves through the existing import map; the kit is CDN-free because the models are local. |
| `model: 'gltf'` builder | `MODELS.gltf(g, v)` is synchronous: it starts (or reuses) the load for `v.gltf.url` and returns at once; when the scene arrives and the active vehicle is still the same build (a generation counter `CAR_GEN` bumped by `buildCar`), a **clone** of the cached scene is fitted and added to `g`. Until then the car group holds only flames/blinkers — the vehicle is invisible for the first frames, physics is unaffected. | `setVehicle` stays synchronous (tests, hooks, picker in #7 call it directly); physics never depends on the mesh. |
| Fit | `fitTransform(box, length, yaw)` (pure, `prototype/vehicle.js`): uniform scale so the model's extent along its long horizontal axis = `v.gltf.length` metres; rotate by `yaw` so the front faces **+x** (the game's forward: compact's headlights sit at x = +2.2); translate so the box's min y = 0 and its x/z centre = 0. `yaw` is a table value tuned once per model. | Kenney models' native size and facing are unknown until inspected; the entry says what the result must be, in metres. |
| Wheels for glTF vehicles | The kit's wheel model is placed at each `wheels: [[x, z], …]` position (mirrored ±z, like `buildCompact`), scaled so its diameter = `2 · wheelR`. Nodes named `wheel*` inside the vehicle `.glb`, if the kit has them, are **not** used in this issue. | One convention (the table) for all vehicles; discovering attachment empties is a nice-to-have. |
| Disposal | `freeCar` (`:890`) skips geometries/materials carried by cached glTF scenes: objects added from the cache are tagged `userData.shared = true` (clone shares geometry/material with the cache) and `freeCar` leaves those alone. Procedural parts (wheels built by the kit loader are also cache clones, so they're shared too). | `test_rebuilds_free_gpu_memory` must stay flat for glTF rebuilds as well. |
| Collision shape `obb` | `collision: { shape: 'obb', hl, hw, bounce }` in model metres: half-length along the heading, half-width. Implemented as a **capsule approximation**: `obbSamples(hl, hw)` (pure, `vehicle.js`) returns sample offsets along the long axis — `[0]` when `hl − hw < 1e-9`, otherwise `n = max(2, ceil((hl − hw) / hw)) + 1` evenly spaced points from `−(hl − hw)` to `+(hl − hw)` — and `collide` runs the existing circle test once per sample point with radius `hw`, displacing the whole vehicle by each push. Corners are rounded by `hw`. No yaw torque from collisions in this issue. | Reuses the proven circle-vs-OBB code (`:991`) and the obstacle grid unchanged; 12 m bus = 5 samples at ±4.7, ±2.35, 0 with r 1.3. Predictable, testable, no new solver. |
| Collision shape `circle` | Unchanged: `{ shape: 'circle', r, bounce }`; `carRadius()` stays `r · scale`. | Compact must drive bit-for-bit as before. |
| `bounce` | New per-vehicle field = the restitution factor that is the literal `1.25` in `collide` today. `compact.collision.bounce = 1.25` (explicit, so the golden trace holds), tractor `1.25`, bus `1.0` (no rebound: the normal velocity is removed, the bus slides along the wall). | "Pushes obstacles instead of bouncing": nothing movable exists, so the bus's heaviness is `mass` (less speed loss, less damage) plus no rebound. |
| Shadow blob | Circle → as today `(scale, 0.55·scale)`; obb → `(hl / 2.6 · scale, hw / 2.6 · scale)`. | The 12 m bus needs a 12 m shadow; compact unchanged. |
| `checkVehicle` | Accepts `model` in `MODELS` (now `compact`, `gltf`); for `gltf` requires `def.gltf` with `url` (string), `length` (> 0), `yaw` (number). Accepts `collision.shape` `'circle'` (`r > 0`) or `'obb'` (`hl ≥ hw > 0`); anything else throws `Error("Vehicle collision shape 'x' is not supported, only 'circle' or 'obb'")`. Missing `collision`, inherited `model` names (`Object.hasOwn`) keep throwing `Error`. | Fail fast stays; the #6 placeholder text goes. |
| `?vehicle=<id>` | `vehicleFromQuery(search, ids)` (pure, `vehicle.js`) returns the id if `?vehicle=` names a key of `VEHICLES`, else `null`; `index.html` calls `setVehicle(VEHICLES[id])` at startup when set. Unknown ids are ignored silently. No key binding. | Players (and the Playwright tests) can reach the new vehicles before #7 exists; the keyboard is full (`:914`). |
| Tractor entry | `tractor: { model: 'gltf', gltf: { url: 'models/car-kit/tractor.glb', length: 4.4, yaw: <tuned> }, scale: 1.0, wheels: [[1.3, 0.95], [-1.1, 0.95]], wheelR: 0.55, drive: { top: 11.1, topNitro: 16, accel: 6, accelNitro: 10, brake: 14, reverse: 4, reverseMax: 6, grip: 30, gripHandbrake: 12, steerRate: 2.2, airSteer: 0.2 }, mass: 2.5, collision: { shape: 'circle', r: 1.4, bounce: 1.25 }, camera: { chase: { dist: 10, h: 3.8 }, near: { dist: 7, h: 2.8 }, cockpit: { eye: [-0.3, 2.3, 0] }, bumper: { eye: [2.2, 0.9, 0] } }, sound: { horn: [300], hornDur: 0.5, engineBase: 30, enginePerRpm: 60, gears: [0, 10, 20, 30, 999] } }` | 40 km/h = 11.1 m/s; grip 30 vs compact 9 (`vs *= exp(−grip·dt)`: sideways speed gone in a few frames), handbrake grip 12 > compact's normal grip ("hardly slides"); a 4.4 m tractor is one circle. Nitro stays a game mechanic for every vehicle (58 km/h). Big rear wheels come from the model; the table's `wheelR` is the kit wheel's fitted size. |
| Bus entry | `bus: { model: 'gltf', gltf: { url: 'models/car-kit/bus.glb', length: 12, yaw: <tuned> }, scale: 1.0, wheels: [[4.2, 1.1], [-3.6, 1.1]], wheelR: 0.5, drive: { top: 22, topNitro: 28, accel: 4, accelNitro: 8, brake: 10, reverse: 3, reverseMax: 5, grip: 6, gripHandbrake: 1.2, steerRate: 1.1, airSteer: 0.2 }, mass: 8, collision: { shape: 'obb', hl: 6, hw: 1.3, bounce: 1.0 }, camera: { chase: { dist: 20, h: 6.5 }, near: { dist: 13, h: 4.5 }, cockpit: { eye: [5.0, 2.4, -0.6] }, bumper: { eye: [6.1, 0.8, 0] } }, sound: { horn: [349, 440], hornDur: 0.8, engineBase: 38, enginePerRpm: 70, gears: [0, 15, 30, 50, 70, 999] } }` | 80 km/h top (Swiss bus limit), accel a quarter of the compact's, steerRate 1.1 vs 2.6 = wide turns, mass 8 = crash speed loss ≤ 1/8. ## Out of scope

- The Car Select screen (#7), stat bars, paint colours.
- Engine/horn synthesis changes (#14).
- Shrinking the compact to real size (#69).
- Movable/pushable obstacles, yaw torque from collisions, OBB-vs-OBB (vehicle vs vehicle — there is one vehicle).
- Surface-dependent handling (fields, gravel): no hook exists; the tractor's "good on fields" is its grip.
- Wheel animation (spin/steer), wheel attachment empties from the kit.
- Own Blender models (later, per the issue).

4. **OBB collision** (hand layout, Smile-Kreisel island at (1206.5, −127), radius 9.5): a bus copy (`shape: 'obb', hl: 6, hw: 1.3`) standing at (1218.3, −127) heading π/2 (long axis along z, side towards the island, side clearance 11.8 − 1.3 = 10.5 > 9.5) is **not** moved; the same bus heading 0 (long axis along x, rear sample at 1218.3 − 4.7 = 1213.6, 7.1 m from the centre) is pushed out until its rear sample clears: centre at 9.5 + 1.3 + 4.7 = **15.5 m** (±0.05) from the island centre.
5. **Bounce** — a compact copy with `bounce: 1.0` coasting head-on into the island at 15 m/s ends with lower speed than `bounce: 1.25` (no rebound component), and `bounce: 1.25` reproduces `test_table_mass_softens_the_crash`'s `light` value 2.074.
6. **Tractor drive** — `setVehicle(VEHICLES.tractor)` then `sim` from START: 4 s on the gas ends between 8.5 and 11.1 m/s (flat-road estimate ≈ 9.3: `11.1·(1 − e^(−6·4/11.1))` minus drag). Grip: `window.__mm.sim` additionally returns `vx, vz` (additive change); after 1 s of W+D+Ctrl at 15 m/s the **slip angle** (angle between the velocity vector and `heading()`) is below 2° for the tractor (`gripHandbrake: 12` → sideways speed decays by e⁻¹² per second) and above 10° for the compact (`1.8`).
7. **Bus drive** — 4 s on the gas ends below 14 m/s (compact 31.47); the `turn` scenario (2 s W+A at 15 m/s) ends with a heading change below 60 % of the compact's (`steerRate` 1.1/2.6 = 0.42, the slower bus gets a slightly larger speed factor `sf`).

10. **Startup selection** — `?vehicle=bus` → `window.__mm.vehicle().model === 'gltf'` and `collision.shape === 'obb'`; `?vehicle=tank` → compact.
11. **Strings** (`strings.test.mjs` pattern): `credits` exists in `en` and `de`.

## Assumptions

- **A1** [confirmed] Models come from the Kenney Car Kit (CC0), loaded as glTF, vendored into the repo (no CDN at runtime for models), credited in the game. The bus is a generic yellow bus without PostAuto logo, lettering or the three-tone horn (`docs/07-brands-and-permissions.md`, tracker row "PostAuto"). User decision 2026-10-03.
- **A2** [low] ⛔ **The Car Kit may contain no bus.** The kit's description and tags name sedan, van, ambulance, firetruck, trucks, karts and a tractor; no public listing names a bus, and the kit's file list could not be read from this session (web lookups capped). Rejected: silently substituting the kit's `van`/`delivery` stretched to 12 m (a stretched van is not a bus and `fitTransform` scales uniformly). The spec therefore fixes the bus's path, footprint, colour and "no livery" rule and leaves the **file's source** to a human: Kenney bus if it exists, else a CC0 Quaternius bus (the issue's own alternative), else a procedural `buildBus`. Everything else in this issue is independent of that choice.
- **A3** [high] `GLTFLoader` is imported from `three/addons/loaders/GLTFLoader.js` via the existing import map (`index.html:198`), not vendored. Rejected: vendoring three.js's loader — three itself already comes from the same CDN, so vendoring one addon buys nothing. Verified reachable (HTTP 200).
- **A4** [med] A long vehicle collides as a capsule (circles of radius `hw` along the long axis) rather than a true OBB-vs-OBB solver. Rejected: SAT between the vehicle box and each obstacle box — a new solver for one vehicle, with no gameplay difference at 1.3 m corner rounding. Evidence: `collide` at `index.html:991` already does circle-vs-OBB and circle-vs-circle exactly.
- **A5** [med] "Pushes obstacles instead of bouncing" is implemented as `mass: 8` (existing `collide` formula divides speed loss and damage by mass, `index.html:991`) plus a new per-vehicle `bounce` (restitution) of `1.0` for the bus. Rejected: movable props — nothing in the obstacle grid moves (`pushOBB`, `index.html:480`; `PROP_SOLID`, `:675`), and making lamps/bins dynamic is its own feature.
- **A6** [med] The tractor's "good on fields" is realised solely through grip (`grip: 30`, `gripHandbrake: 12`). Rejected: adding surface-dependent drag — `stepCar` (`index.html:998`) has no surface term today and adding one changes the compact's feel (golden trace).
- **A7** [med] New vehicles are reachable through `?vehicle=<id>` only (no key). Rejected: a cycle key — every letter near the home row is taken (`index.html:914`), and #7 owns vehicle selection UI. Evidence: `?debug` precedent (`debug.js:5`, `index.html:1126`).
- **A8** [med] Kit wheels are placed from the table's `wheels` positions (compact's convention, `index.html:881`), not from attachment nodes inside the `.glb`. Rejected: node-name discovery — the kit's node naming is unverified from this session; the table convention is already tested.
- **A9** [med] `setVehicle` stays synchronous and the glTF arrives later into the live car group (generation-guarded). Rejected: `await`ing the model in `setVehicle` — `window.__mm.setVehicle` is called synchronously by ten existing tests and will be by #7.
- **A10** [high] Compact stays at `scale: 1.3`; the new vehicles are `scale: 1.0` in real metres. Rejected: shrinking compact here — that is #69, enriched in parallel.
- **A11** [med] The credit lives on the start panel (new `credits` string under `#blurb`) and in README's License section. Rejected: a new credits screen — no such surface exists and the pause menu (#83) is still a plan.
- **A12** [med] The `sound` values for tractor and bus fill today's `VEH.sound` shape; #14 will reshape them. Rejected: waiting for #14 — the entries must be complete for `SFX.update`/`hud()` to run (`index.html:928`, `:1127`).
- **A13** [med] The `#6`-placeholder assertions in `test_vehicles.py::test_set_vehicle_validates_and_round_trips` are rewritten (the behaviour they pinned was "not yet implemented"). Rejected: keeping them — they would contradict the feature.

## Consequences

- Until #69 lands, the 1.3× compact (5.85 m) is longer than the real-size tractor (4.4 m) when seen side by side on the start screen or after switching.
- The first frames after selecting a glTF vehicle show flames/blinkers and the shadow but no body (model still downloading). On a cold load this is tens of milliseconds for a Kenney `.glb`.
- `collide` runs 5 circle tests per frame for the bus instead of 1 — negligible against `gridQuery`.
- The bus's nose scrapes along walls without turning (no yaw coupling); corners feel "slidey" rather than "hooked".
- The nitro key works for all three vehicles (a tractor at 58 km/h with blue flames) — a game mechanic, not a vehicle property.
- The `enrichment-ongoing` state of #14 and #69 means their entries may rename `sound`/scale fields after this lands; the three entries are then edited together.
- `test_set_vehicle_validates_and_round_trips` loses its `#6` assertions; the validation surface is wider (gltf, obb) and tested for both.
