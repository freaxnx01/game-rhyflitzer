# `oneway` and `lanes` per road in the world file (#679)

## Goal

Every road piece in `world_*.json` carries its travel direction (`oneway`) and its OSM lane count (`lanes`), so later work (lane keeping in the autopilot #678, multi-lane roundabouts #680, Postauto lines #500/#682, motorway traffic #681) can read them without going back to OSM. Pipeline and data only. No game code reads the fields in this issue.

## Today

- `pipeline/world_roads.py:132-137` writes `id, n, cls, w, mark, bridge, layer, [trail], pts` per piece. `lanes` is read only inside `marking()` (`world_roads.py:63`); `oneway` is never read.
- `world_extra_roads._piece_roads` (`pipeline/world_extra_roads.py:58-60`) reuses `world_roads.build`, so game-only roads follow the same code path.
- `world.js` reads only known keys (`r.w`, `r.mark`, `r.n`, `r.pts`), so extra optional keys are inert.
- Probe on `pipeline/cache/osm/hochrhein.osm.pbf` (14256 highway ways): `oneway` on 1014 (651 `yes`, 360 `no`, 3 `-1`), `lanes` on 1649 (1:373, 2:1009, 3:243, 4:21, 5:3), 36 roundabout ways and none of them carries a `oneway` tag. The two Kreisel candidates named on the issue: way 195099803 has `lanes=1`, way 672824132 has `lanes=2` (both `junction=roundabout`, `highway=primary`).

## Design

Two new optional keys per road piece:

- `"oneway": true` - present only on one-way roads. Absent means two-way or unknown. **`pts` is always in the travel direction**: a way tagged `oneway=-1` (or `reverse`) has its points reversed at build time, so a consumer never needs to know about `-1`.
- `"lanes": <int>` - present only when the OSM `lanes` tag is a whole number >= 1. For a two-way road it is the total over both directions, for a one-way road the lanes of that carriageway (OSM semantics). Absent means unknown; width is never used to guess it.

`oneway` rules (OSM defaults): explicit `yes`/`true`/`1` forward; `-1`/`reverse` reversed; any other explicit value (`no`, `reversible`, `alternating`) means not one-way; with no tag, `junction=roundabout|circular`, `highway=motorway` and `motorway_link` are one-way. Trails (`trail_ids`) get neither key.

Both keys are copied to every piece when `build` splits a way at solid/broken marking changes (`_pieces` keeps point order).

Format `MMW1` stays: adding optional keys is backwards compatible. `docs/11-pipeline-osm.md` documents them. The two shipped world files are regenerated by the implementer from the cached extracts when present.

## Consequences

- The Kreisel candidates from the issue comment: way 195099803 is `lanes=1` in OSM, so after this issue the world file shows one lane there, not two. Whether the double-lane roundabout is way 672824132 (`lanes=2`) or needs an override in `anchors.json` is #680's question, not decided here.
- `world_hochrhein.json` grows by well under 0.2 MB uncompressed (about 1650 lane keys and 1000 oneway keys of ~12 bytes, plus 36 roundabouts).
- A rebuild also picks up any pipeline change merged since the last build; the golden tests (`test_golden.py`) show such drift.
- An explicit `oneway=no` on a motorway or roundabout removes the implicit flag (explicit value wins).

## Acceptance Criteria

- [ ] `world_roads.build` emits `"oneway": true` for `oneway=yes|true|1`, and for roundabouts, `motorway` and `motorway_link` without a `oneway` tag.
- [ ] An explicit `oneway=no|reversible|alternating` yields no `oneway` key, also on a roundabout or motorway.
- [ ] `oneway=-1` (and `reverse`) yields `oneway: true` with `pts` reversed (first point is the way's last point).
- [ ] `build` emits `"lanes": n` for a whole-number `lanes` tag >= 1; no key for a missing, `0`, non-numeric or `2;3` value.
- [ ] Trail pieces carry neither key; every piece of a split way carries the keys.
- [ ] `oneway` and `lanes` survive clipping: a way crossing the clip box keeps its direction.
- [ ] `docs/11-pipeline-osm.md` documents both keys in the schema line and a short rules section.
- [ ] Pipeline tests pass (`cd pipeline && python -m pytest`); the golden test asserts way 672824132 has `oneway` true and `lanes` 2 when the extract exists.
- [ ] `data/world_hochrhein.json` and `data/world_ehrendingen.json` regenerated with the new keys, or the PR states which extract was missing.
