# Delivery mode (pizza, parcels) to a given address — design

Status: approved in headless `/enrich` (quick mode, no human gate) 2026-10-03 · Issue #107 · needs #18 (routing) and #106 (Navi), uses #104/#105 (impact strength)

## Goal

Issue #107: "Neuer Spielmodus: Ausliefern (Pizza, Pakete). Es wird eine Zieladresse vorgegeben." The user decided on 2026-10-03: a **time-chase with real addresses**. A pizzeria is the start point, a random real house address is the target, a time limit plus a time bonus applies, the **Navi** (#106) shows the way, every delivery pays points or tips and the best score is saved, and the **cargo suffers when you crash** (#104 / #105 impact strength).

Success: on the start screen a **Delivery** button starts a **shift** of 5 orders. The car stands at the pizzeria. Each order shows an address ("Bodenackerstrasse 6c"), a countdown and the cargo condition. The Navi leads to it. Stopping at the marker in front of the house within the time hands over the pizza and pays a tip: more for a long route, more for time left, less for a damaged cargo. After the fifth order a result screen shows the shift total and the saved best.

## Starting point (verified 2026-10-03 on `main` @ `ee94c5e`)

- **Neither dependency is merged.** #18 (`docs/superpowers/specs/2026-10-03-autopilot-design.md`, plan on `main`) and #106 (`2026-10-03-navi-design.md`, plan on `main`) are open; `prototype/route.js` and `prototype/navi.js` do not exist. #104 (`2026-10-03-crash-sound-design.md`) is open: `prototype/impact.js` does not exist. #105 (wreck / damage) is open and has no spec on `main`. **Task 0 of the plan checks all three files and stops.**
- **What the dependencies will provide.** #18: `route.js` with `buildGraph(roads)`, `snapToGraph(g, x, z, maxDist)` → point or `null`, `findRoute(g, start, goals)` → route `{ pts, cum, len, joints }` or `null`; the road graph is the largest connected network (96.6 % of nodes, #18 A4) and excludes `footway`, `path`, `steps`, `cycleway`, `pedestrian`. #106: `startNavi({ n, x, z })` and `stopNavi()` (the interface section of its spec), `__mm.navi()`. #104: `impactStrength(speed)` = `clamp01((speed - 3) / 22)` from `prototype/impact.js`, "the only definition of impact strength", called with the closing speed `-vn` at a wall hit (`collide`, `index.html:1071`) and `-vy` at a landing (`stepCar`, `index.html:1084`).
- **Addresses exist.** `data/world_hochrhein.json`: 1,892 buildings, **1,328 with `addr`**. Of those, 1,186 are plain (`6`, `36A`, `6c`); the rest are ranges (`14-18`, `6a–6d`) and oddities (`65/1`). **1,245 have a mapped road within 40 m, 1,118 of them a *named* road** (dry run on the file with the #18 road filter, 2026-10-03). The data has **no per-building street**: `pipeline/world_buildings.py` exports only `addr`, so the street is the nearest named road (the same rule #71 uses for the plate side, `2026-10-03-house-number-plates-design.md`).
- **No restaurants in the world file.** `props` hold only lamps, benches, hydrants, bins, bike racks and recycling containers (`pipeline/world_props.py:20-27` maps only those amenities; `pipeline/osm_read.py:16,33` keeps no restaurant). `anchors.landmarks` has no pizzeria either. So a "real OSM restaurant" cannot come from the data without a pipeline change and a new world file.
- **Race.** `R = { state: 'ready' | 'armed' | 'racing' | 'finished', … }` (`index.html:1111`); `startRace` (`:1119`) hides the overlay; `stepCar` is skipped in `'ready'`; `finish` records `mm.best2` only when `!R.jumped && !R.flown`. **R is not the race restart**: `KeyR` calls `resetCar()` (`index.html:973`), the car goes back to `P.safe`. The race starts with the **Start** button (`#startbtn`, `:200`).
- **Persistence precedent.** `localStorage` holds `mm.odo`, `mm.best2` (progress: best time, odometer) and `gg-lang`; night (#2) deliberately does not persist (a look). Every access is in `try/catch`.
- **Pause (#83, merged):** `canPause(overlayHidden, raceState)` allows `armed` / `racing` only (`prototype/pause.js:10`); `needsAbandonConfirm(raceState)` asks only for `racing`.
- **Cheats the mode must know about:** J teleport (`placeOnRoad`, `:1012`, sets `R.jumped`), helicopter F (`FLY.on`, sets `R.flown`), the autopilot O (#18, sets `R.auto`), map double-click jump.
- **Toasts / HUD:** `toast(html, secs)`, `TOAST_S = { info: 4, event: 5 }` (`:1115`); `#tc` centred column, `#tl` top left, `#tr` top right (time), `#navi` panel (#106) right under the compass. Strings in `prototype/strings.js` through `tr()`, `strings.test.mjs` enforces equal en/de keys and no `ß`.

## Decisions

| Topic | Decision |
|---|---|
| Mode | A **shift** = **5 orders** in a row, started from the start screen. State machine in a pure, node-tested module `prototype/delivery.js`; `index.html` keeps the glue. Race and delivery are separate: Start = race, **Delivery** = shift. |
| Starting it | A second button **Delivery** (`#deliverybtn`) in the start screen's `.row`, next to Start; shown in the hand layout but disabled with the hint "Needs the OSM world". It uses the current vehicle (#7 car select, #5 table). Pause menu (#83) **Restart** during a shift starts a new shift; **Main menu** ends it (with the abandon question, as in a race clock). Not a pause-menu entry and not a car-select option. |
| Coexistence | `R.state = 'delivery'` while a shift runs (new value). `stepRace` only acts on `armed` / `racing`, so no clock and no checkpoints run; the checkpoint rings and the finish gate are hidden during a shift. `canPause` / `needsAbandonConfirm` accept `'delivery'`. **Start** (race) ends a running shift silently. `mm.best2` and the race are untouched. |
| Pizzeria | **Hand anchors, invented names, no logos** (A2): three depots, each placed by a landmark and resolved at load to the nearest addressed building within 120 m of it: *Pizza Fridolin* (near Fridolinsmünster, Bad Säckingen), *Pizza Rheinblick* (near Bahnhof Stein-Säckingen, Stein), *Pizza Sissla* (near Gemeindehaus Sisseln). One is picked at random per shift. The car is placed on the nearest routable road, facing along it (same helper as J, `placeOnRoad` without the `jumped` flag). The depot is a landmark-style marker (a coloured pillar, like the checkpoint pillars) and a minimap dot labelled with its name. |
| Address pool | `buildAddresses(buildings, nearestNamedRoad)`: buildings with a **plain** house number (`^\d+[a-zA-Z]?$`, so `6`, `36A`, `6c`; ranges and `65/1` are left out) and a **named routable road within 40 m** of the building centre (street = that road's `n`). Label `"<street> <number>"` (1,100+ entries expected). The point `x, z` is the building centre. |
| Reachable | An address is a target only if `snapToGraph(g, x, z, 60)` lands on the **main network** (the graph already is the largest network) **and** `findRoute` from the car to it exists. The graph's own filter drops footways and the 3.4 % of stubs. The drop point is the snapped point (on the road in front of the house), not the building centre. |
| Distance band | Per order: route length **400 m – 3,000 m** from where the car stands. Pick random addresses (seeded), reject the last 3 used, reject outside the band, at most 200 tries; if none fits, widen the band to 250 m – 5,000 m once; if still none, toast "No order right now" and end the shift (cannot happen on this map). |
| Time limit | `timeLimit(len) = max(45, round(25 + len / 9))` seconds (A4): route length over a **reference speed of 9 m/s (32 km/h)**, which is below the autopilot's class caps of 30–60 km/h (#18) because of bends, junctions and the stop, plus **25 s grace**. A 1.5 km order gets 192 s, a 600 m order 92 s. |
| Handing over | Delivered when the car is within **10 m** of the drop point **and** slower than **1.5 m/s** (A5), checked each step. Rejected: only "within X m" (a fly-by would count); a full stop at 0. Not during `FLY.on` (blocked anyway). A rotating marker pillar stands at the drop point and a dot on the minimap; the target address is also in the HUD. |
| Scoring | `tip = round((base + bonus) × cargo / 100)`: `base = round(len / 10)` (1.5 km → 150), `bonus = 2 × whole seconds left`. Late or ruined → 0 for that order. Shift score = sum of the tips. |
| Late | The clock reaches 0: the order is lost, toast "Too late — order lost", the next order is drawn from where the car stands. |
| Cargo | Starts at **100 %** per order. `hitCargo(cargo, strength)`: `cargo − 40 × strength`, floored at 0, with `strength = impactStrength(speed)` from `prototype/impact.js` (#104, shared with #105). A bump under 3 m/s costs nothing, a full-speed wall hit 40 %. At 0 % the pizza is ruined: order lost, toast "The pizza is ruined". Hook: the same call sites that play `SFX.crash` also call `deliveryImpact(strength)` (landings via `-P.vy`). It does **not** read #105's wreck/damage state, so it works if #105 lands later or never; if #105 adds a damage value later, it only has to call the same hook (A6). |
| Reset key | **R** (`resetCar`) stays allowed during a shift (a stuck car, #36) and costs **15 s** of the current order's clock. |
| Cheats | While a shift runs: **J**, the map double-click jump, **F** (helicopter, #10) and **O** (autopilot, #18) are ignored with the toast "Not during a delivery" (A7). Rejected: letting them through with a "not counted" flag (the score is the point of the mode; there is no race result to mark). The Navi **I** key is ignored too — the shift owns the Navi (it is started and stopped by the mode). |
| Navi | Each order calls `startNavi({ n: label, x: drop.x, z: drop.z })` (#106's interface); a new order stops the old one first; the end of the shift calls `stopNavi()`. Replanning, the panel and the minimap route line are the Navi's own. The Navi's arrival toast at 20 m ("Arrived: <address>") ends the Navi before the 10 m handover; the marker pillar and minimap dot take over for the last stretch (A8). |
| Persistence | `mm.deliveryBest` in `localStorage` (the best shift **score**, a number), `try/catch` around every access, like `mm.best2`. It is progress, so it persists (A9); nothing else of the shift is saved. |
| HUD | A line stack in `#tc` under `#roadname`: `Order 2/5 · Bodenackerstrasse 6c`, the countdown (red under 20 s), `Cargo 85 %`, `Score 210`. Empty outside a shift. Rejected: a plate top left (collides with the debug panel on touch phones, #106 A10) and the right column (the Navi panel lives there). |
| Result screen | `renderOverlay` shows, when a shift is over: "Shift done", the total, `n of 5 delivered`, the best (`New best!` when beaten) and the **Delivery** button again ("Another shift"). **Start** still starts the race. |
| Pure logic | `prototype/delivery.js` (no DOM, no three.js): `DELIV` constants, `parseHouse`, `buildAddresses`, `resolveDepots`, `timeLimit`, `orderScore`, `hitCargo`, `isHandover`, `pickOrder`, `newShift`, `beginOrder`, `tick`, `applyImpact`, `applyPenalty`, `finishOrder`, `isNewBest`, `mulberry32`. A seeded generator, never `Math.random` inside the module. Tested with `node --test`. |
| Strings | `startDelivery`, `deliveryNeedsWorld`, `delivOrder`, `delivCargo`, `delivScore`, `delivLate`, `delivRuined`, `delivDone`, `delivHandOver`, `delivNoCheat`, `delivShiftDone`, `delivResult`, `delivNewBest`, `delivAnother`, `delivPickup`, `delivNoOrder`, `keyDelivery`. |
| Test hooks | `__mm.delivery()` → `{ on, phase, idx, order: { label, x, z, len, left, cargo }, score, best, depot }`; `__mm.deliveryStart(seed)` starts a shift; `__mm.deliveryTeleportToDrop()` puts the car on the drop point at rest (the test cannot drive 1.5 km); `__mm.deliveryImpact(strength)`. |

## Interactions with other features

- **#18 autopilot:** counts as cheating: O is ignored during a shift (an autopilot would make the mode a spectator sport). The router, graph and A\* are used by the mode as-is for reachability and route length.
- **#106 Navi:** the shift drives it through `startNavi` / `stopNavi`. The mode adds no routing and no panel.
- **#104 / #105 impact:** `impactStrength` is the one definition (#104 A4). #105's wreck is independent: a wreck at 100 % damage respawns a car (its own rule); the shift treats the respawn as `resetCar` (15 s penalty) if #105 uses `resetCar`, otherwise nothing special — the cargo is judged only by impacts.
- **#10 helicopter:** not allowed during a shift (F ignored). A running flight cannot start a shift (the button is on the start screen, where `FLY.on` is already false after the finish).
- **#71 house-number plates:** if #71 is merged, the target house's plate is not highlighted in this issue (out of scope, A10); the address is in the HUD and the marker stands at the road in front of it. A highlight is a follow-up on #71's `addrPlates` output.
- **#83 pause:** frozen with the game; the countdown does not run while paused (the step block is skipped). Restart / Main menu as above.
- **#7 car select:** any vehicle works; the bus and the tractor (#6) too. Not part of the shift.
- **#2 night / #14 sound:** untouched. A delivered/late/ruined jingle would be new sound: not now.
- **#12 street names:** the street shown in the HUD comes from the road names in the world file, the same as the HUD road name.

## Assumptions

- **A1** [high] [confirmed] A time-chase with real addresses: a pizzeria is the start, a random real house address the target, a time limit plus a time bonus, the Navi (#106) shows the way via `startNavi` / `stopNavi`, points or tips per delivery with the best score saved, and the cargo suffers when you crash (#104 / #105 impact strength). Decided by the user 2026-10-03.
- **A2** [med] The pizzeria is a **hand anchor with an invented name**, placed by a landmark, not an OSM `amenity=restaurant/fast_food`. Evidence: the world file has no restaurant (props are lamps, benches, hydrants, bins, bike racks, containers; `pipeline/world_props.py:20-27`), so real OSM restaurants would need a pipeline change and a new `data/world_hochrhein.json` (a data change with its own review). No real names or logos (user). Rejected: a pipeline change in this issue; the Bahnhof as depot (not a pizzeria).
- **A3** [med] Addresses come from buildings with a plain house number and a named routable road within 40 m; the street is the nearest named road, not a mapped `addr:street`. Evidence: 1,328 buildings have `addr`, the data has no street (`pipeline/world_buildings.py`), 1,118 sit within 40 m of a named road. Rejected: adding `addr:street` to the pipeline (data change); using ranges (`6a–6d` has no single door).
- **A4** [med] Time limit = 25 s + route length / 9 m/s (minimum 45 s); band 400 m – 3 km. Rejected: the autopilot's class speeds (too fast for a human with bends and a stop); no minimum (a 150 m order gets 42 s of nothing to do); longer routes (the Navi dozes, the Fridolinsbrücke crossing would need its 30 km/h rule). The numbers are a table (`DELIV`), tuning is a playtest edit.
- **A5** [med] Handover = within 10 m of the drop point and below 1.5 m/s. Rejected: a pure radius (drive-by); a full stop on a spot (the drop point is the nearest road point, not exactly the door).
- **A6** [med] Cargo loss `40 × impactStrength` per hit, floored at 0, ruined at 0 %. Rejected: coupling to #105's damage value (not specified on `main`); a flat loss per crash (a tap would cost as much as a wall at 90 km/h).
- **A7** [med] J, F, O, map jump and the Navi key are ignored during a shift; R is allowed with a 15 s penalty. Rejected: flagging cheats as "not counted" like the race (no result to flag); forbidding R (a car stuck at a wall would end the shift, #36).
- **A8** [med] The Navi's own 20 m arrival toast and end are accepted; the marker and minimap dot cover the last 20 m. Rejected: patching #106 to suppress the toast or run to 10 m (a change in another feature's module); a second guide in this issue.
- **A9** [high] Only the best shift score persists (`mm.deliveryBest`). Evidence: `mm.best2` and `mm.odo` are progress and persist, night (#2) is a look and does not (`index.html:1112`, `:1007`).
- **A10** [med] The target house is not highlighted (#71's plates are not merged); the address text and a road-side marker identify it. Rejected: blocking this issue on #71.
- **A11** [med] A shift is 5 orders, ending with a result screen; each order starts where the previous one ended, not at the pizzeria. Rejected: an endless chain with game over on the first miss (harsh for a first mode); a return trip to the pizzeria for every order (doubles the driving without a decision in it); a fixed daily list (needs a calendar).
- **A12** [med] Start from a button on the start screen. Rejected: a key (I and O are claimed by #106 / #18, and a mode switch is not something to press mid-drive); the car-select screen (a mode is not a car); the pause menu (it only exists inside a run).
- **A13** [high] New UI text through `tr()` with en and de entries (`strings.test.mjs` enforces equal keys and no `ß`).

## Consequences

- The start screen has three buttons in a row (Start, Delivery, Style) plus #2's night button; narrow phones wrap it.
- A shift is about 5–8 minutes of driving (5 orders × up to ~3 km at 9 m/s).
- Players can park next to a house for a perfect handover tip: the bonus rewards speed, the cargo rewards care, and nothing punishes a bump under 3 m/s.
- Street names with letters (`6c`) read fine in German ("Bodenackerstrasse 6c") and the same in English; streets exist twice on the two banks of the Rhine ("Hauptstrasse" / "Hauptstraße", #18 consequence), so two addresses can look alike.
- The Navi's "Arrived" toast comes at 20 m, 10 m before the handover is possible.
- A crash while someone else's feature hooks `collide` earlier (e.g. #105) must keep calling `deliveryImpact`; the hook is one line at each existing `SFX.crash` call site.

## Out of scope

Parcels as a second cargo type (the mode's data model has a `cargo` string, but only the pizza exists), a pickup leg, several customers per order, tips by customer mood, a leaderboard, real OSM restaurants (needs a pipeline change), a highlight of the target house's plate (#71), sounds and jingles, a touch button, difficulty levels.
