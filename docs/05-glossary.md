# Glossary: graphics terms

Short explanations of the graphics and 3D terms used in these docs.

## Geometry

**Vertex**: a point in 3D space. The corner of a triangle.

**Triangle / polygon**: the basic building block of all 3D surfaces. GPUs only draw triangles; every other shape is broken down into them.

**Mesh**: a 3D object made of vertices and triangles, e.g. a house or a car.

**Low-poly**: models with deliberately few triangles. Cheap to render; as a style, clean and graphic.

**Footprint**: the 2D outline of a building as seen from above, as stored in OSM or cadastral data.

**Extrusion**: pulling a 2D footprint up to a given height, turning it into a 3D block. Works for any angle, not just 90°.

**Normal**: the direction a surface faces. Lighting depends on it.

**UV mapping**: how a 2D texture is wrapped onto a 3D mesh. Each vertex gets a coordinate in the texture.

## Textures and materials

**Texture**: an image applied to a surface, e.g. plaster, roof tiles, asphalt.

**Texture atlas**: many small textures packed into one big image. Fewer texture switches for the GPU, so faster.

**Texture filtering**: how a texture looks when it's shown larger or smaller than its pixel size. `LinearFilter` blends pixels (smooth, blurry). `NearestFilter` takes the nearest pixel (hard, chunky). The MM1 look uses `NearestFilter`.

**Material**: describes how a surface reacts to light: color, texture, shininess, roughness.

**Shader**: a small program running on the GPU that computes the position of each vertex (vertex shader) and the color of each pixel (fragment shader). Procedural facades are typically done in a shader.

**Procedural**: generated by rules and code instead of made by hand. Example: windows placed automatically based on a building's width and height.

**Baking**: pre-computing expensive information (lighting, detail from a high-poly model) into a texture, so it doesn't have to be calculated at runtime.

## Lighting and look

**Vertex lighting / Lambert**: simple, cheap lighting that only considers the angle between surface and light. Typical of late-90s games.

**Flat shading**: each triangle gets one uniform color, so the faceted low-poly shape stays visible. Typical of the slowroads look.

**Shadow map**: shadows computed by rendering the scene from the light's point of view. Looks good, costs performance.

**Fog**: objects fade into a color with distance. Hides where the world stops loading, and sets the mood.

**Post-processing**: effects applied to the finished image, e.g. color grading, bloom, pixelation.

**Color grading**: adjusting the colors of the whole image to create a mood (warm evening, cold morning).

**Render resolution**: the resolution the scene is actually drawn at. Rendering lower and scaling up gives the chunky retro look and saves performance.

**Style profile**: in this project, a bundle of materials, lighting and post-processing that can be swapped at runtime to change the graphic style without touching the world data.

## Performance

**Draw call**: one instruction from the CPU to the GPU to draw something. Too many draw calls are a typical bottleneck. Merging meshes reduces them.

**Merging**: combining many meshes (e.g. all houses in a chunk) into one, so they cost one draw call instead of hundreds.

**Instancing / InstancedMesh**: drawing the same mesh many times (trees, lamps, traffic cars) in one draw call, each with its own position.

**LOD (level of detail)**: showing simpler versions of objects the further away they are. Distant objects only cover a few pixels, so the missing detail isn't visible.

**Terrain LOD**: LOD applied to the ground. Near the car the terrain is finely meshed, in the distance coarsely.

**Quadtree**: a way of dividing an area: split a square into four, split those into four again, and so on. Used for terrain LOD: fine subdivision near the player, coarse far away.

**Popping**: a visible jump when an object switches from one LOD level to another.

**Cracks / skirts**: where a fine terrain tile meets a coarse one, gaps (cracks) can appear. Skirts are small vertical strips at tile edges that hide them.

**Vertex morphing**: smoothly blending vertices between LOD levels instead of switching abruptly. Avoids popping.

## World and streaming

**Tile / chunk**: a square piece of the world (e.g. 1 × 1 km) that is loaded and unloaded as a unit.

**Streaming**: loading tiles in the background as the player approaches, and dropping ones they've left behind.

**Floating-point precision / origin rebasing**: 3D coordinates are stored as floating-point numbers, which get imprecise far from the origin (jitter). Origin rebasing periodically shifts the whole world so the player is near 0,0,0 again.

## Geodata terms

**LoD1 / LoD2 (CityGML)**: not the same as graphics LOD. In geodata, LoD describes how detailed a building model is: LoD1 is a plain block, LoD2 adds real roof shapes.

**CityGML**: an XML-based standard format for 3D city models.

**DEM / DGM / DOM**: elevation models. DGM (Digitales Geländemodell) is the bare ground; DOM (Digitales Oberflächenmodell) includes buildings and trees. DEM is the general English term.

**Orthophoto**: an aerial photo corrected so it's geometrically accurate like a map. Useful as ground texture or color source.

**Photogrammetry**: building a 3D model from many photos taken from different angles.

## Game terms

**Hero asset**: a hand-made, detailed model of an important landmark (Holzbrücke, Fridolinsmünster), as opposed to procedurally generated buildings.

**Hudmap**: the minimap on screen during a race.

**Raycast vehicle**: a common way to simulate cars: instead of real rotating wheels, rays are cast downward from the car body to find the ground and compute suspension and grip.

**Rubber-banding**: AI opponents speed up when behind and slow down when ahead, so races stay close.

## Platform

**WebGL / WebGPU**: browser APIs to use the graphics card. WebGL is established; WebGPU is its modern successor. three.js supports both.

**WASM (WebAssembly)**: a fast binary format running in the browser. Rapier's physics engine is compiled to it.

**Buildless**: no bundler or build step; the browser loads ES modules directly.
